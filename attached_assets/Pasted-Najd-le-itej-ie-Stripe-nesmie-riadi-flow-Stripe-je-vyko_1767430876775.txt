2️⃣ Správna produktová logika (toto si zapíš)
Stav súťaže

Používaj dva oddelené stavy (toto je kľúčové):

competition.status: 'draft' | 'ready' | 'live' | 'finished'
competition.paymentStatus: 'unpaid' | 'paid'

Význam:

draft → rozpracovaná súťaž

ready → kompletná, čaká na štart

live → prebieha

finished → skončená

💡 Platba nikdy nemení status priamo.
Platba iba nastaví paymentStatus = paid.

5️⃣ Prečo ti teraz svieti „Vybrať balík a zaplatiť“ (pravda bez obalu)

👉 Cache + zlý zdroj pravdy

Momentálne:

UI sa pozerá na staré query

Stripe redirect príde skôr než invalidateQueries

UI sa rozhoduje podľa paymentStatus z cache

Fix (povinný):

po návrate zo Stripe:

await queryClient.invalidateQueries(['/api/organizer/competitions'])


a UI sa MUSÍ pýtať:

if (competition.paymentStatus !== 'paid') showPayButton


Nie podľa URL. Nie podľa redirectu.
Iba podľa dát.

6️⃣ UX verdikt (úprimný)

❌ Výber balíka na konci = UX fail

❌ Platba pred konfiguráciou = UX fail

❌ Stripe ako „mozog aplikácie“ = architektonický fail

Ale:

✅ Rozdelenie výber balíka / platba = výborné rozhodnutie

✅ Stripe až na konci = profesionálny produkt

✅ Limity počas wizardu = presne to, čo čakajú organizátori
